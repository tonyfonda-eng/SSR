# Operations Centre & Secret Screener Audit

**Date:** August 2, 2026  
**Auditor Target:** SSR Institutional Engineering  
**Focus:** Data Pipeline Completeness & HTML Representation  

## 1. Executive Findings
The Operations Centre HTML Dashboard effectively parsed basic volumetric data but was systematically "dropping" critical upstream intelligence generated by SQLite and the `MetricsCollector`. The visual layer abstracted away vital granular data, specifically masking AI failure origins and source filtration mechanics.

Furthermore, the "Secret Screener" (Gitleaks integration) existed purely in the CI/CD environment and local file structures, completely decoupled from the central Operations Centre view.

## 2. Missing Data Identified & Reclaimed
The following operational telemetry was tracked in Python/SQLite but absent from the HTML outputs prior to this audit:

- **AI Provider Masked Keys:** Logged in SQLite but hidden in HTML. *Fix implemented: Keys are now surfaced (masked to last 4 chars) to identify which rotated API key is rate-limiting.*
- **AI 503s, Timeouts, and Fallbacks:** Critical for diagnosing OpenRouter/Gemini network faults. *Fix implemented: Added to the AI Telemetry matrix.*
- **Granular Funnel Deconstruction:** The dashboard mathematically merged ontology and regex drop-offs. *Fix implemented: Funnel rows explicitly separated.*
- **Operational Bottlenecks:** System logged `slowest_stage` per article but failed to aggregate it. *Fix implemented: Added lightweight Top Issuers and Slowest Stages aggregators.*
- **Run ID & Workflow Version:** No traceability. *Fix implemented: Added directly to the top-level header context.*

## 3. Secret Screener Integration Strategy
The Secret Screener relies on `detect-secrets` and Gitleaks SARIF artifacts. Integrating this deeply into the dashboard would require computationally expensive parsing of external JSON schemas, violating the "fast/free" HTML generation rule.
- **Fix Implemented:** A zero-compute `os.path.exists()` check was added to `html_generator.py`. The dashboard header now actively displays a badge ("Baseline Secured", "Scan Artifact Present", or "Not Scanned") based on local security state files, bringing security awareness to the Operations Centre without degrading runtime performance.

## 4. Archive Re-Alignment
The `archive.html` file functioned as a raw list of articles, abandoning the "Event-Centric" philosophy of the project.
- **Fix Implemented:** The HTML table and filtering logic were rewritten to expose `Event Family` and `Outcome`, turning the archive into a searchable operational state ledger rather than a mere URL dump.

## 5. Remaining Limitations & Recommendations
- **Remaining Quota Estimation:** Still deferred. Fetching active billing balances from AI providers requires synchronous network calls during the dashboard build loop, increasing the risk of pipeline timeout.
- **SQLite Optimization:** The dashboard still relies heavily on the 100-item memory stack (`logs`) passed from the orchestrator. If the orchestrator transitions to asynchronous workers, `html_generator.py` will require a direct SQL read capability to calculate Top Issuers and bottlenecks reliably.
